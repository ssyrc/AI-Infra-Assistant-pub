# AI Infra Assistant

사내 인프라·시스템 운영 문의를 받아 **매뉴얼과 과거 문의(VOC)에서 근거를 찾고, 필요하면
사용자 본인 권한으로 커맨드를 실행해** 한국어로 답하는 에이전트.

- 폐쇄망 전용. 외부 API 호출 없음.
- LLM·임베딩·리랭커 전부 사내 vLLM.
- 답변 근거는 **매뉴얼 / 과거 사례 / 실행 결과** 셋뿐. 그 밖은 지어낸 것으로 간주하고 차단.

---

## 1. 무엇을 푸는가

| 문의 유형 | 예 | 답의 출처 |
|---|---|---|
| **어떻게 하는가** | "GPU 서버 접속 방법" | 매뉴얼 |
| **왜 안 되는가** | "로그인 서버 접속 불가" | 과거 사례(VOC) + 매뉴얼 |
| **내 값이 얼마인가** | "내 홈 용량" | **실행해야만** 확인 가능 |

세 번째가 핵심. 계정마다 다른 값은 문서에 존재할 수 없으므로 실제 조회가 필요하고, 그 조회는
**반드시 문의한 사용자 본인 권한**으로 수행.

        CONSOLE["관리자 콘솔 :8501<br/>매뉴얼·VOC·커맨드·설정"]

        subgraph mcp["MCP 서버 · streamable HTTP · 루프백만 개방"]
            M1["Manual MCP<br/>매뉴얼 검색"]
            M2["VOC MCP<br/>과거 사례 검색"]
            M3["Execution MCP<br/>커맨드 실행"]

        PG[("PostgreSQL + pgvector<br/>manual · voc · execution<br/>config · session · memory")]
    end

    subgraph gpu["GPU 서버 · 사내 vLLM"]
        LLM["LLM<br/>Qwen3-235B-A22B"]
        EMB["임베딩<br/>bge-m3 · 1024차원"]
        RRK["리랭커<br/>bge-reranker-v2-m3"]
    end

    LOGIN["게이트/로그인 서버<br/>계정 홈 · 스케줄러"]

    U --> WEBUI --> AGENT
    SH -->|"POST /v1/voc/query"| AGENT
    OPS --> CONSOLE --> PG
    AGENT <--> M1 & M2 & M3 & M4
    M1 & M2 & M3 --> PG
    AGENT -->|"추론"| LLM

    M3 -->|"ssh · 본인 계정으로 강등"| LOGIN

| 구성요소 | 역할 |
|---|---|
| **agent-server** | 요청 처리의 중심. 질문 계획 → 선검색 → 에이전트 실행 → 근거 검사 → 후처리 |
| **Manual MCP** | 매뉴얼 청크 하이브리드 검색. 읽기 전용 |
| **VOC MCP** | 과거 문의·답변 하이브리드 검색. 읽기 전용 |
| **Execution MCP** | 커맨드 실행 전담. 등록 커맨드는 각각 전용 도구, 그 밖은 `run_command` |
| **Chart MCP** | 수치를 SVG로 변환. 실행·DB 조회 없음 |
| **관리자 콘솔** | 매뉴얼/VOC 적재, 커맨드 등록, 설정, VOC 처리주체 분류 |
| **Open WebUI** | 사용자 채팅 화면. agent-server를 OpenAI 호환 모델로 연결 |
| **Service Hub** | 사내 VOC 시스템 연동. 접수된 문의를 API로 위임 |

## 3. 요청 하나가 처리되는 과정

```mermaid
sequenceDiagram
    autonumber
    participant U as 사용자
    participant A as agent-server
    participant L as vLLM
    participant R as 검색 · Manual/VOC
    participant X as Execution MCP

    U->>A: 질문
    A->>L: ① 질문 계획 요청 · JSON 한 개
    L-->>A: mode · sources · queries
    alt mode = execute
        Note over A: 근거 블록 미첨부<br/>실행으로 답할 질문
    else mode = search
        A->>R: ② 선검색 · 멀티 쿼리
        R-->>A: 매뉴얼·VOC 근거
    end
    A->>L: ③ 지시문 + 근거 + 도구 목록
    L-->>A: 도구 호출
    A->>X: ④ 커맨드 실행 · 본인 계정
    X-->>A: exit_code · stdout · duration_ms
    A->>L: 실행 결과 전달
    L-->>A: 답변 초안 · 스트리밍
    Note over A: ⑤ 근거 검사<br/>남의 계정·미근거 값 제거
    A-->>U: 진행 줄 + 최종 답변 + 실행 원문
```

**각 단계의 설계 의도**

| 단계 | 하는 일 | 왜 |
|---|---|---|
| ① 질문 계획 | 실행/검색 판별, 필요한 근거 선택, 검색어 2~3개 생성 | LLM 왕복 한 번으로 라우팅·질의재작성 동시 해결 |
| ② 선검색 | 코드가 먼저 검색해 프롬프트에 근거 주입 | 모델에게 맡기면 "안다"고 판단해 검색을 건너뜀 |
| ③ 에이전트 | 근거를 읽고 도구 선택. 진행 상황을 사람 말로 중계 | 도구 이름 비노출, 실제 커맨드만 표시 |
| ④ 실행 | argv 리스트로 ssh 실행 후 본인 계정 강등 | 셸 미경유, 파괴적 명령 차단 |
| ⑤ 근거 검사 | 근거에 없는 IP·경로가 든 **줄만** 제거 | 지시문은 확률, 검사는 확정 |

**설계 원칙 두 가지**

- **검색 여부를 모델이 정하지 않음.** 지시문으로 네 번 강제했으나 모델이 반복적으로 건너뜀.
  코드가 먼저 검색하면 "검색을 안 했다"는 실패 자체가 성립하지 않음.
- **사용자가 반드시 알아야 하는 것은 LLM을 거치지 않는 경로로 표시.** 실행 결과 원문,
  진행 상황, 지어낸 값 차단 셋 다 코드 경로.

## 4. 실현한 기법

### 4-1. 검색 (RAG)

| 기법 | 내용 | 해결한 문제 |
|---|---|---|
| **하이브리드 3축 검색** | 벡터(bge-m3) + 키워드(tsvector) + 3-gram(pg_trgm word_similarity) | 의미·정확일치·오타를 한 번에 |
| **RRF 융합** | 축별 순위를 `1/(60+rank)` 합산 | 점수 스케일이 다른 축을 정규화 없이 결합 |
| **접두 질의** | `to_tsquery('simple', '서버:* \| 위치:*')` | `simple` 사전은 형태소 분석 부재. `서버` ≠ `서버별`로 키워드 축이 사실상 사문화 |
| **멀티 쿼리** | 계획 단계가 만든 다른 표현으로 후보 추가 수집 | 사용자 문장과 문서 표현의 불일치. "서버 위치" vs "서버별 Location" |
| **후보/리랭킹 분리** | 질의는 여럿, **리랭킹은 원 질문 기준 1회** | 질의마다 리랭킹 시 리랭커 왕복이 질의 수만큼 증가 |
| **Cross-encoder 리랭킹** | bge-reranker-v2-m3로 재정렬 후 하한 적용 | RRF 상위가 곧 정답은 아님 |
| **Contextual retrieval** | 리랭커 입력에 `등록제목 > 문서명 > 섹션` 접두 | 청크 본문만으로는 무엇에 대한 문서인지 판별 불가 |
| **MMR 중복 제거** | 유사도 임계 초과 결과 제거 | 유사 문의가 상위를 독점 |
| **이웃 청크 확장** | 앞뒤 청크를 같은 문서 안에서만 연결 | 절차 문서의 중간 단계 누락 방지 |
| **예산 우선 배치** | 찾은 청크의 자리를 먼저 확보 후 남는 만큼만 이웃 부착 | 이웃이 예산을 소진해 **정작 검색된 표가 잘려 나감** |
| **선검색 강제** | 매 질문 코드가 먼저 검색 | 모델의 도구 호출 누락 |

### 4-2. 에이전트

| 기법 | 내용 |
|---|---|
| **질문 계획** | 실행/검색 · 근거 선택 · 검색어 생성을 JSON 한 개로 수신. 파싱 실패 시 전부 안전한 기본값으로 강등 |
| **근거 미첨부 전략** | 실행이 필요한 질문에는 매뉴얼·VOC를 **의도적으로 미첨부**. 근거가 보이면 모델이 그것으로 답하고 실행을 생략 |
| **현재 질문 고정** | `# 이번에 답할 질문` 블록을 프롬프트 선두에 주입. 앞 질문 이어받기 차단 |
| **주입 블록 우선** | 실행 규칙을 DB 지시문이 아닌 매 요청 주입 블록에 배치. 지시문 미반영 상태와 무관하게 적용 |
| **도구 선택 편향 보정** | 일반 실행기를 도구 목록 선두 배치 + 등록 도구마다 "이 커맨드의 출력만 반환" 명시 |
| **진행 중계** | MCP 종류별로 사람이 읽는 한 줄 생성. 도구 이름 비노출, 실제 커맨드만 표시 |
| **스트리밍 델타 정규화** | ADK의 누적/증분 혼재 이벤트를 접두사 추적으로 증가분만 전송 |
| **툴콜 파싱 복구** | 스트리밍 툴콜 JSON 파싱 실패 시 논스트리밍으로 1회 자동 재시도 |
| **차트 인라인** | Chart MCP는 짧은 표시자만 반환, 응답 직전 data URI로 치환. 대화 이력에는 표시자만 잔류 |

### 4-3. 답변 신뢰성

| 기법 | 내용 |
|---|---|
| **근거 검사** | 답변의 IP·절대경로를 근거 집합과 대조. 미근거 값이 든 **줄만** 제거 |
| **부분 보존** | 남은 문장이 실질 내용이면 유지, 전무하면 운영팀 안내로 대체 |
| **실행 원문 병기** | 도구 결과 원문을 LLM 경로 밖에서 답변에 첨부 |
| **처리 주체 분류** | 과거 사례를 LLM이 `user`/`operator`/`unknown`으로 판정해 저장 |
| **추측형 강제** | 운영자 처리·판정 불가 사례는 원인을 **여러 가능성**으로 제시. 단정 금지 |
| **개인정보 마스킹** | 검색 결과의 계정·이메일·이름·조직을 MCP 반환 **이전에** 자리표시자로 치환 |
| **계측** | 도구 호출·결과·소요 시간, 검색 단계별 건수, 계획 결과를 전부 로그화 |

## 6. 보안 — 커맨드는 **문의한 사용자 본인 권한으로만** 실행

### 6-1. 실행 경로 전체

```mermaid
flowchart TB
    Q["사용자 질문"] --> W["Open WebUI"]
    W -->|"Authorization: Bearer agent_api_key<br/>X-User-Id: 로그인 계정"| A["agent-server"]
    A -->|"X-MCP-Secret: 공유 비밀값<br/>X-User-Id · X-User-Roles"| M["Execution MCP"]

    M --> C1{"1 · 도구 인증"}
    C1 -->|"비밀값 불일치"| D1["401 거부"]
    C1 --> C2{"2 · 역할 검사<br/>required_roles"}
    C2 -->|"불충족"| D2["거부"]
    C2 --> C3{"3 · user_id 강제 주입<br/>LLM 스키마에서 은닉"}
    C3 --> C4{"4 · 인자 검증<br/>타입·선택지·개수·길이"}
    C4 --> C5{"5 · 차단 목록<br/>모든 토큰 검사"}
    C5 -->|"rm · dd · sudo · bash …"| D3["거부"]
    C5 --> C6{"6 · 타 계정 지목 차단<br/>-u 남 · --user=남"}
    C6 -->|"본인 아님"| D4["거부"]
    C6 --> S["argv 리스트 구성<br/>셸 미경유"]
    S --> SSH["ssh root@host"]
    SSH --> DROP["즉시 권한 강등<br/>su-login / su / runuser"]
    DROP --> RUN["사용자 계정으로 실행"]
    RUN --> LOG["실행 이력 기록<br/>계정 · 커맨드 · exit_code · 소요"]
```

### 6-2. 각 층이 막는 것

| # | 장치 | 막는 공격/사고 |
|---|---|---|
| 1 | **MCP 공유 비밀값** | 같은 망의 임의 프로세스가 MCP를 직접 호출. db-init이 무작위 생성, 양쪽이 같은 DB에서 조회 |
| 2 | **역할 검사** | 권한 없는 사용자의 커맨드 사용 |
| 3 | **`user_id` 은닉·주입** | LLM이 남의 계정을 지정. 스키마에서 감추고 호출자 헤더에서 강제 주입 |
| 4 | **인자 명세** | 미등록 옵션·과다 인자·과장 길이. 선택형은 스키마에 값 고정 |
| 5 | **차단 목록 전 토큰 적용** | `mpirun … rm -rf /`, `bash -c "…"` 류 우회 |
| 6 | **타 계정 지목 차단** | `phd list -u 남의계정`. OS 권한으로는 못 막음. 판정 주체가 그 프로그램이기 때문 |
| 7 | **셸 미경유** | 파이프·리다이렉션·와일드카드·명령 치환 전부 무력화. argv 리스트로만 실행 |
| 8 | **root 실행 금지** | `ssh root@host` 직후 **항상** 호출자 계정으로 강등. 우회 경로 미제공 |
| 9 | **내부 포트 루프백 한정** | postgres·MCP 4종은 `127.0.0.1`에만 개방 |
| 10 | **실행 이력** | 계정·커맨드·인자·exit_code·소요를 DB 기록. 사후 추적 가능 |

### 6-3. 데이터 보호

| 대상 | 처리 |
|---|---|
| 검색된 남의 계정·이메일 | MCP 반환 **이전에** 자리표시자로 치환. 프롬프트에 원문 미유입 |
| 답변에 등장한 타 계정 | 근거 유무와 무관하게 해당 줄 제거 후 "확인 불가" 안내. 질문에 적혀 있어도 동일 |
| 조직·이름 | 매뉴얼은 계정·이메일만 마스킹(조직명은 절차의 일부). VOC는 전체 마스킹 |
| **실행 결과** | **마스킹하지 않음.** 실행은 항상 본인 권한이므로 결과의 계정·경로는 전부 본인 정보 |

| 저장소 | 내용 |
|---|---|
| `manual_db` | 매뉴얼 문서·청크·임베딩(`vector(1024)`), 문서 위치 |
| `voc_db` | 과거 문의/답변, 임베딩, **처리 주체**(`handled_by`) |
| `execution_db` | 등록 커맨드와 인자 명세, 실행 이력 |
| `platform_config` | 전역 설정(모델 주소, 임계값, 스위치). 콘솔이 CRUD |
| `agent_session` / `memory` | 대화 세션, 장기기억 |

**처리 주체(`handled_by`)** — "답변에 적힌 조치를 사용자가 자기 권한으로 재현 가능한가"를
LLM이 판정해 저장한 값(`user` / `operator` / `unknown`). 에이전트는 이 값으로
*방법 안내* 와 *원인 추측 + 접수 안내* 를 구분.

---

## 8. 배포

폐쇄망이라 GitHub 직접 접근 불가. **WSL 경유 rsync**로 반입.

```mermaid
flowchart LR
    GH["GitHub<br/>공개 미러"] --> WSL["WSL<br/>인터넷 가능"]
    WSL -->|"rsync"| GATE["게이트 서버"]
    GATE --> HOST["폐쇄망 배포 호스트"]
    HOST --> DC["docker compose<br/>마운트 재시작"]
    WSL -.->|"requirements 변경 시<br/>이미지 tar 전송"| GATE
```

| 변경 대상 | 반영 방법 |
|---|---|
| 코드만 | rsync + 재시작. 소스 마운트라 재빌드 불필요 |
| requirements / Dockerfile | 이미지 재빌드 → tar 전송 → load → 재태깅 |
| 새 설정 키 / 마이그레이션 | `db-init` 재실행 |
| 등록 커맨드 추가·수정 | `execution-mcp` 재시작. 도구 목록 재구성 |
| 시스템 지시문 | 콘솔 "최신 기본값으로 되돌리기" → agent-server 재시작 |

## 9. 개발

```bash
bash scripts/verify.sh      # 테스트 + lint + 콘솔 JSX + 셸 문법. 커밋 전 필수
```

- **파이프로 묶지 않음.** `pytest … | tail && git commit`은 종료코드를 가려 실패한 테스트를
  그대로 통과시킴.
- 회귀 테스트는 **구현의 모양이 아니라 규칙**을 검사. 새 규칙 추가 시 **일부러 깨뜨려**
  실제로 잡히는지 확인.
- 원인 분석과 결정은 `docs/HISTORY.md`에 번호를 이어 기록. 같은 문제를 두 번 추측하지 않기
  위한 유일한 기억.

## 11. 공개용 사본

사내망이 외부 코드 호스팅으로의 **인증된 접근**을 차단하므로 private 저장소는 WSL에서 수신
불가. **코드만** 자리표시자로 치환한 공개 사본을 별도 운용.

```bash
bash scripts/make-public.sh     # dist/public/ 생성 + 검사. 실패 시 종료코드 1
bash scripts/scan-internal.sh   # 내부 정보 잔존 여부 단독 검사
bash scripts/push-public.sh     # 검사 통과 시에만 공개 미러에 반영
```

공개본은 히스토리 미포함(커밋 1개). 옛 블롭에 원문이 남을 경로 자체를 제거.
